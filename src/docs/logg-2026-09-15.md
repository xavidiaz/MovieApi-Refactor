## Vad som gjordes (förmiddag)

### `MovieService.CreateAsync` — färdigställd

- Byggdes i tre omgångar innan den satt: (1) försök med `Actors = createDto.ActorsId`
  direkt (typfel, `int` ≠ `Actor`), (2) försök att blanda `Where`/`Select` med
  `foreach` och `await` inuti en lambda (kompilerar inte, fel verktyg), (3) landade
  först i en ren `foreach`-loop som slår upp varje `Actor` en och en via
  `unitOfWork.Actors.GetByIdAsync(id)`.
- **Repo-lagret utökades** med en batch-metod: `IActorRepository.GetByIdsAsync
  (IEnumerable<int> ids)`, implementerad i `ActorRepository` som en enda fråga
  (`context.Actors.Where(a => ids.Contains(a.Id)).ToListAsync()`). `CreateAsync`
  skrevs om att använda den istället för `foreach`-loopen — en fråga istället för
  N, samma tysta-hoppa-över-beteende för id:n som inte finns.
- `IEnumerable<Actor>` från `GetByIdsAsync` behöver spridas till `ICollection<Actor>`
  vid tilldelning (`Actors = [.. actors]`) — samma mönster som redan användes för
  DTO-mappningarna.
- Retur: sparad `Movie` (med riktigt `Id` efter `CompleteAsync`) mappas till
  `MovieDto`, samma mönster som `GetByIdAsync`.

### `IMovieService.cs` — synkad

Alla fem metodsignaturer uppdaterade från `Movie`/`Movie` till DTO-baserade:
`GetAllAsync` → `IEnumerable<MovieDto>`, `GetByIdAsync`/`CreateAsync`/`UpdateAsync`/
`DeleteAsync` → `MovieDto`/`CreateMovieDto`. `using`-raden bytt från `Entities` till
`Dtos`.

`Movie → MovieDto`-mappning för hand, trots att `MovieService.GetAllAsync` redan
returnerar `MovieDto`. Städat: returtyp ändrad till `Task<IEnumerable<MovieDto>>`,
manuell mappning borttagen.

## Vad som gjordes (eftermiddag/kväll)

### `UpdateMovieDto` — skapad

- Diskuterade formen mot `CreateMovieDto`: `Title`/`Year`/`ActorsId`, inga
  `Reviews` (recensioner uppdateras inte via film-uppdatering). `ActorsId` gjordes
  `required` medvetet — PUT är en full ersättning, ingen klient ska kunna
  utelämna den och råka tömma skådespelarlistan tyst.
- `init` vs `set` och redundanta `= string.Empty`/`= []`-defaults på `required`-fält
  diskuterades (jämfört med `MovieDto`s rena `init`-utan-default-mönster).
  `CreateMovieDto.Title` städades (`= string.Empty` borttagen); `UpdateMovieDto`
  landade med `init` konsekvent.

### `MovieService.UpdateAsync` — färdigställd, samma typ av friktion som `CreateAsync`

- Första försöket mappade `movie.Actors` (som är `ICollection<Actor>`, entitet)
  till en lista av `ActorSummaryDto` — typfel. Andra försöket byggde **nya**
  `Actor`-objekt via `actorsDb.Select(a => new Actor {...})` istället för att
  använda de redan hämtade, spårade entiteterna direkt — hade dubbeltrackat EF
  Core (samma `Id` i två objekt) och tappat `Actor.Movies`-navigationen. Landade
  rätt: `movie.Actors = [.. actors];` direkt på de entiteter som redan kom från
  `GetByIdsAsync`, exakt samma mönster som `CreateAsync`.
- Retur-DTO byggs inline (`MovieDto` med nästlad `Actors`/`Reviews`-mappning),
  samma mönster som `GetByIdAsync`/`CreateAsync`/`DeleteAsync` — ingen delad
  mapping-helper än (AutoMapper kommer Fas 9, ingen prematur abstraktion).

### `MovieRepository.GetByIdAsync` — saknad `.Include()` hittad och fixad

Den kända begränsningen från gårdagens logg bekräftades: `FindAsync` laddade
varken `Actors` eller `Reviews`. `FindAsync` stödjer inte `.Include()`
(query-komposition), så metoden skrevs om till:

```csharp
public async Task<Movie?> GetByIdAsync(int id) =>
    await context.Movies
        .Include(m => m.Actors)
        .Include(m => m.Reviews)
        .FirstOrDefaultAsync(m => m.Id == id);
```

Detta påverkade `GetByIdAsync`, `UpdateAsync` och `DeleteAsync` i servicen (alla
läser `movie.Reviews` utan att själva sätta den).

### `MoviesController` — POST/PUT/GET`{id}`/DELETE tillagda — #78 stängd

Alla fyra byggdes med samma återkommande lärdom: **controllern ska bara
delegera**, inte återimplementera det servicen redan gör.

- **POST** (`CreateAsync`): första försöket hämtade en film via `GetByIdAsync`
  istället för att skapa en (kopierade fel mönster). Andra försöket byggde om
  retur-DTO:n manuellt trots att `serviceManager.Movie.CreateAsync(...)` redan
  returnerar `MovieDto`. Landade i en enda expression-bodied rad.
- **PUT** (`PutAsync`): samma sak — första försöket hämtade filmen som `MovieDto`
  och försökte mutera `.Title`/`.Actors` på den (kompileringsfel: `MovieDto` har
  `init`-properties, inte `set`). Löstes genom att inse att `MovieService.
  UpdateAsync(id, inputDto)` redan gör hela jobbet — controllern blev en rad.
- **DELETE** (`DeleteAsync`): skrevs korrekt direkt, samma delegerings-mönster,
  ingen rättning behövdes.
- **GET `{id}`** (`GetByIdAsync`, lades till som fjärde, ej ursprungligen i #78
  men rimlig att ta med): några rena syntaxmisstag (`[HttpGet(Name = "Movie/
  {id}")]` istället för `[HttpGet("{id}")]`, saknad parametertyp, `=> return`
  som inte går ihop med expression-body) rättades till.

**Krångel:** efter att `GetByIdAsync` lagts till gav `GET /movies/1` ett
500-fel — `System.ArgumentNullException: Value cannot be null. (Parameter
'modelName')` i ASP.NET Cores model binding. `PUT`/`DELETE` band redan `int id`
från samma sorts route utan problem, så det var inte routingen/attributen i sig.
Löstes genom att **starta om `dotnet run`/`dotnet watch` helt** — troligen ett
hot-reload-relaterat metadata-glapp för den senast tillagda action-metoden.
**Värt att minnas:** om en helt ny controller-action ger konstiga fel direkt
efter tillägg, testa omstart innan djupare felsökning.

Commit: `Fas 8 Steg 3: Lägg till GET/{id}, PUT och DELETE i MoviesController med
DTO-baserad mappning. Closes #78` — pushad.

## Svårt idag — flaggat för extra övning

- **Nästlad DTO-mappning** (Actor/Review inuti Movie) — själva mönstret
  (`[.. collection.Select(x => new XDto {...})]`) satt inte på rak arm, behövde
  upprepas flera gånger med handledning innan det klickade.
- **`Select` vs `Where`** — förväxlades upprepade gånger (transformera vs filtrera).
- **`await` inuti LINQ-kedjor** — försökte flera gånger klämma in ett asynkront
  anrop mitt i en `Select`/`Where`-lambda; behövde brytas ut till en vanlig
  `foreach`-loop istället, sen vidare till en riktig batch-metod i repot.
- **Entitet vs DTO vid tilldelning** (nytt idag) — flera gånger byggdes en ny
  DTO eller en ny entitet via `Select(x => new X {...})` på data som redan var
  av rätt typ och bara skulle tilldelas direkt (`movie.Actors = [.. actors]`
  utan mellansteg). Samma rotproblem som Select/Where-förväxlingen, men på
  tilldelningsnivå istället för filtrering.
- **Controller som återimplementerar service-logik** (nytt idag) — `POST`/`PUT`
  i `MoviesController` byggdes först som fullständiga implementationer (hämta,
  mutera, spara) istället för en enda rad som delegerar till servicen. Samma
  missförstånd tre gånger (`CreateAsync`, `PutAsync`, och nästan `ActorDto`-
  vägen) innan det satt.
- **Förslag (kvarstår från igår):** en liten, fristående LINQ-drill utan DB/async,
  ren mappning/filtrering på in-memory-listor, innan nästa DTO-runda
  (Review-controllers, #80–82).
